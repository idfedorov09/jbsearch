# Proposal

Статус: **Implementation in progress**, разрешено пользователем 2026-11-03.
Find/Replace реализованы на нативном modal-подходе; готовность выпуска определяется
проверками задач. Платформенная проверка macOS и Windows остаётся открытой.
Клиентский канал темы/grammars принят и разрешён 2026-11-04; его проверки
учитываются отдельно от более раннего прототипа native preview.

## Why

Нужен поиск по файлам с компактным списком совпадений и preview, как в JetBrains,
который можно свободно перемещать и разворачивать во вкладку VS Code. До этого
изменения в заготовке существовала только проверка установки.

## What Changes

Подтверждено пользователем:

- По Cmd+Shift+F появляется компактный плавающий диалог поверх текущего окна
  редактора, как Find in Files JetBrains; он перемещается и меняет размер.
- UI преимущественно на стандартных компонентах VS Code, с наследованием
  текущей темы и оформления; результаты и preview находятся внутри диалога.
- Отдельное окно редактора и отдельное приложение не считаются автоматически
  эквивалентными этому UX. «Открыть во вкладке» — дополнительное действие.
- Целевые платформы сразу: macOS, Windows и Linux.
- Нужны scopes, маски файлов, многострочный запрос, case/word/regex-переключатели,
  клавиатурное управление, preview и переход к тому же поиску во вкладке.
- ADR/OpenSpec должны сопровождать проект.

Принято для реализации после технической проверки:

- Выбран штатный modal editor VS Code с webview CustomEditorProvider.
  Обычный VSIX проверен на stock VS Code 1.144.1 Linux/X11. Открытие использует
  внутреннюю команду: зависимость принята с проверкой совместимости; это не публичный API.
- Нативная рамка VS Code; внутри — semantic HTML controls с переменными `--vscode-*`.
  Они наследуют оформление webview; внутренние widgets workbench через API не экспортируются.
- Отдельное desktop-приложение и detached editor не нужны этому пути.
  Для Remote preview добавлен небольшой стандартный UI extension на клиенте;
  серверный компонент продолжает выполнять поиск и строить единый webview.
- Общая сессия поиска для диалога и вкладки.
- Локальный ECMAScript matcher в отдельном worker, учитывающий изменённые открытые
  документы; bundled ripgrep перечисляет файлы с учётом ignore.
- Нативные настройки VS Code для постоянных предпочтений, быстрые фильтры в окне.
- Регистрация исходной папки через штатный Install Extension from Location и
  Reload Window без повторной переустановки VSIX. Remote SSH поиск проверен
  отдельно; тема и недостающие grammars поступают с клиента через команды VS Code.
- Клиентский компонент читает активную тему, includes, token customizations и
  grammar resources без передачи ему запросов или найденного кода. Он включён
  в основной пакет и автоматически устанавливается штатным механизмом VS Code
  при первом Remote preview. Ошибка настройки видна в preview; есть команда повтора.

Дополнительно подтверждено: layout максимально близок Find/Replace in Files
JetBrains, preview снизу с syntax highlighting и выделением matches;
Cmd+Shift+R / Ctrl+Shift+R открывает Replace с Replace и Replace All.
Горячие клавиши Find и Replace включены по умолчанию, отключаются в Settings.

Не входят в этот change: символы/семантический поиск, VCS-only scopes,
Marketplace, автопубликация, DOM-патчи редактора. Реализация включает настоящий поиск и замену, не демонстрационные данные.

## Capabilities

### New Capabilities
- `search-window`: плавающее окно, маршрутизация к workspace, keyboard UX, вкладка и preview.
- `text-search`: запросы, scopes, маски, ignore, результаты и отмена.
- `text-replace`: одиночная/массовая замена, проверка актуальности и штатный Undo.
- `search-preferences`: постоянные настройки и состояние сессии в памяти без истории на диске.

### Modified Capabilities
- `installation-check`: статус сообщает о доступных Find/Replace, без запуска поиска.

## Impact

Изменение затрагивает src/extension.js, contributes/configuration/keybindings,
custom editor provider, адаптер modal-команд, search/session/UI модули,
клиентскую UI-часть, вложенную упаковку, проверки и документацию.
При Remote используются два extension ID: `idfedorov09.jbsearch` и
`idfedorov09.jbsearch-client`; устанавливаемый основной VSIX содержит клиентский.
Runtime-зависимости: @vscode/ripgrep-universal,
vscode-textmate, vscode-oniguruma и jsonc-parser. Отдельный desktop host не требуется.
Preview остаётся TextMate, без semantic tokens. Тему не требуется устанавливать
на сервер. Проверка Remote между разными машинами остаётся открытой.

В manifest установлен минимум VS Code 1.143.1. Появление modal editors в 1.110
не доказывает совместимость конкретного маршрута на всех версиях: проверены
1.143.1 и 1.144.1 Linux/X11; macOS/Windows и следующие версии требуют проверок.

Публичного ViewColumn.Modal нет. Прежний вывод о необходимости патча/форка
пересмотрен по реальному запуску. При useModal: off внутренний вызов открывает
вкладку; адаптер проверяет настройку до вызова, объясняет ограничение и предлагает
Settings, не меняя настройку автоматически.
Реализация разрешена пользователем с этой зависимостью. См. [ADR 0002](../../../docs/adr/0002-floating-search-host.md)
и [протокол эксперимента](../../../docs/research/modal-editor-feasibility.md).
Решение о клиентском канале и границы native-эксперимента — в
[ADR 0006](../../../docs/adr/0006-remote-preview-theme.md).
