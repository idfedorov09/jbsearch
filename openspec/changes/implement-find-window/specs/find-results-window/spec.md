# Spec Delta

## Purpose

Предоставить устойчивое дерево найденных вхождений для последовательного просмотра
и ручного редактирования файлов с возвратом к исходным параметрам поиска.

## ADDED Requirements

### Requirement: Dedicated results presentation
Find Window SHALL показывать отдельную вкладку результатов с деревом корней,
каталогов, файлов и совпадений, кратким описанием запроса и действиями обновления,
навигации и возврата к параметрам. Повторная кнопка Open in Find Window отсутствует.

#### Scenario: Transfer from dialog
- **WHEN** пользователь подтверждает Open in Find Window в modal
- **THEN** открывается отдельная вкладка дерева с тем же запросом, фильтрами и выбранным результатом
- **AND** повторная кнопка переноса и нижний read-only preview в ней не показываются

#### Scenario: Stable ordering
- **WHEN** одинаковый поиск возвращает результаты в разном порядке пакетами
- **THEN** завершённое дерево имеет одинаковый порядок по корню, пути и позиции в файле
- **AND** свёрнутые группы и выбранный результат сохраняются при проверке изменений

#### Scenario: Close results tab
- **WHEN** пользователь закрывает последнюю панель Find-вкладки
- **THEN** её снимок и отложенные проверки освобождаются
- **AND** последующие правки файлов не запускают поиск для закрытой вкладки

#### Scenario: Keyboard after rerun
- **WHEN** новый запуск или подтверждение параметров выбирает первый результат новой выдачи
- **THEN** Enter открывает именно этот видимо выбранный результат
- **AND** промежуточная пустая выдача и завершающая сортировка не сохраняют фокус старой строки

### Requirement: Editable source alongside results
При выборе совпадения продукт SHALL показывать настоящий редактируемый файл
справа от дерева с темой, возможностями языка, обычными сохранением и Undo,
выделяя актуальные совпадения без записи на диск самим поиском. В stock VS Code
используется правая editor group; точный Secondary Side Bar не имитируется.

#### Scenario: Select and edit
- **WHEN** пользователь выбирает совпадение и редактирует показанный файл
- **THEN** изменения происходят в настоящем документе VS Code и доступны другим вкладкам
- **AND** редактор наследует тему, язык и расширения, изменения остаются unsaved до обычного сохранения
- **AND** одиночный выбор результата не крадёт фокус у дерева, Enter переносит фокус в редактор

#### Scenario: Switch results quickly
- **WHEN** пользователь быстро выбирает несколько результатов
- **THEN** справа остаётся последний выбранный файл с его диапазоном
- **AND** дерево и исходные вкладки не заменяются preview-файлом

### Requirement: Retained invalid occurrences
Завершённый поиск SHALL сохранять свой набор результатов до явного повторного
запуска. При изменении документа диапазоны отслеживаются; переставшее совпадать
вхождение обозначается INVALID на прежнем месте дерева, а не исчезает.

#### Scenario: Edit before occurrence
- **WHEN** пользователь добавляет строки перед найденным вхождением
- **THEN** позиция и переход к вхождению смещаются к актуальному тексту без перестановки дерева

#### Scenario: Edit invalidates occurrence
- **WHEN** правка нарушает исходное условие поиска для вхождения
- **THEN** строка остаётся в дереве с INVALID и недоступна для автоматической замены
- **AND** новые вхождения не добавляются до явного повторного запуска

#### Scenario: Undo restores occurrence
- **WHEN** пользователь отменяет правку, из-за которой вхождение стало INVALID
- **THEN** после проверки это же вхождение снова доступно с актуальным диапазоном

#### Scenario: Deleted file or validation error
- **WHEN** исходный файл недоступен либо проверка не завершилась
- **THEN** результат не считается достоверным, состояние обозначается явно и замена блокируется

#### Scenario: Explicit rerun
- **WHEN** пользователь нажимает Rerun Search
- **THEN** поиск заново формирует дерево по сохранённым параметрам, включая новые и исчезнувшие вхождения

### Requirement: Edit originating search
Шестерёнка Find Window SHALL открывать modal с параметрами именно этого поиска.
Подтверждение обновляет исходную вкладку; отмена сохраняет прежний снимок,
а явный New Tab создаёт независимый результат.

#### Scenario: Change query and confirm
- **WHEN** пользователь меняет запрос через шестерёнку и подтверждает его
- **THEN** обновляется та же вкладка Find с новыми параметрами и результатами
- **AND** второй экземпляр этой вкладки не создаётся

#### Scenario: Cancel query changes
- **WHEN** пользователь меняет запрос в modal и закрывает его через Esc
- **THEN** исходная вкладка и её параметры остаются прежними

#### Scenario: New result tab
- **WHEN** пользователь подтверждает Open results in new tab
- **THEN** новый поиск имеет отдельную вкладку и состояние, не заменяя существующий

### Requirement: Guarded replacement
Замены из Find Window SHALL использовать актуальные проверенные диапазоны
и обычный WorkspaceEdit/Undo, блокируя INVALID, pending и неполную выдачу.

#### Scenario: Unsafe occurrence
- **WHEN** выбранное вхождение INVALID или ещё проверяется после редактирования
- **THEN** одиночная замена не применяется по старому диапазону
- **AND** Replace All не применяется, пока набор содержит непроверенные или недействительные вхождения
