# Design

## Context

См. proposal.md. Изменение авторизовано пользователем. SVG содержит только
геометрию, градиенты и metadata, без внешних ресурсов. `.vscodeignore` исключает
`docs/`, но включает `media/`.

## Decisions

- Сохранить предоставленный SVG без изменений в `docs/artwork/icon.svg`;
  raster export 256×256 разместить в `media/icon.png`. Так в VSIX попадает
  готовая иконка, исходник остаётся доступен для дальнейшей работы.
- Использовать обычное поле manifest `icon`, без новых runtime-механизмов.
  Размер соответствует [Extension Manifest](https://code.visualstudio.com/api/references/extension-manifest#fields).
- Не менять внутренний UI-компонент и штатные значки команд/дерева: запрос
  касается иконки основного устанавливаемого расширения.
- Проверять PNG в существующем package verifier: путь из manifest, наличие
  и совпадение с исходным asset, PNG signature и квадратный IHDR минимум 128×128
  (фактический export — 256×256). Новые зависимости
  и отдельные UI-тесты для статического asset не нужны; архитектура ADR не меняется.

## Risks / Trade-offs

Кэш карточки установленного расширения → после обновления исходной регистрации
проверять через Reload Window; установленный VSIX требует переустановки пакета.

## Migration Plan

Проверить изображение и пакет, выполнить check/test/spec:check/package,
записать результат; отправить коммит в `dev` и проверить CI. Публикация отдельно.
