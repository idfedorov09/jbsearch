# JB Search 0.4.2 pre-release preparation

**Status at preparation (November 12, 2026): not published.** This is an update
to the open `dev` → `beta` preparation, not authorization to merge or publish.
It supersedes the unpublished [0.4.1 preparation](v0.4.1-beta.md) and includes
its modal diagnostic correction as well as the search-performance changes.
The extension ID remains `idfedorov09.jbsearch`; the unchanged bundled UI
client remains at 0.1.0 with bridge protocol 1.

## Changes since the published 0.4.0 pre-release

- The modal keeps aggregate binary-exclusion and incomplete-input warnings but
  no longer lists each skipped path or reason. **Open in Find Panel** retains
  bounded representative details. No files are deleted and binary detection
  remains heuristic.
- Intermediate result presentation is coalesced. The first batch and final
  state are delivered promptly; the scheduling interval is not a real-time
  guarantee when the extension host is busy.
- Find avoids replacement approval work. Replacement retains independent
  approval snapshots, stale-action checks and full-scope preflight while
  reducing repeated copying and plan-comparison work for ordinary data.

These are compatible presentation and internal performance changes, without a
new mandatory user step or a reduction in replacement safeguards. Under the
[versioning policy](../versioning.md), a patch is appropriate. The maintainer
requested incrementing the prepared main-extension version to 0.4.2 even though
0.4.1 had not been published. Both Marketplace and Open VSX reported 0.4.0 as
the highest published version when checked on November 12, 2026. Check them
again before any separately authorized publication.

## Verification and release boundary

On the prepared 0.4.2 tree, `npm run check` passed, `npm test` passed 928/928
tests, and `npm run spec:check` passed 37/37 items. A clean isolated `npm ci`
and both stable and marked pre-release package checks passed; each package
contained 90 main and 31 bundled-client entries, and the changed runtime sources
matched the working tree.

The [performance verification record](../testing/search-performance.md)
describes the synthetic workload, automated checks, trade-offs and a separate
native VS Code checklist. Synthetic timings do not establish real VS Code or
Remote performance. Native UI, Windows/WSL, macOS, and physical Remote
acceptance remain unverified for these changes.
