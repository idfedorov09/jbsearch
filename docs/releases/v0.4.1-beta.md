# JB Search 0.4.1 pre-release preparation

**Status at preparation (November 12, 2026): not published.** This note describes
the intended 0.4.1 correction, not a stable release, registry publication, or
platform acceptance. Check the later PR and registry record for current status.
The extension ID remains `idfedorov09.jbsearch`; the bundled UI client remains
at 0.1.0 and its bridge protocol remains at 1. Publication requires separate
authorization.

## Correction and version decision

Relative to the already-published 0.4.0 pre-release, the modal presents only
aggregate binary-exclusion and incomplete-input warnings; it does not list
skipped-file paths, per-file reasons, or omitted-path messages. The existing
**Open in Find Panel** action retains bounded representative paths and reasons
for review. General error, stale-result, and Rerun messages remain available.

Binary detection remains heuristic: a text input can be mistaken for binary,
and some binary data can look like text. Review the representative details in
Find Panel before bulk replacement. Intentional binary exclusions alone do not
make a search incomplete; unreadable or otherwise unsearchable inputs and
existing stale, invalid, or pending checks retain their replacement safeguards.
Search eligibility, completeness classification, and replacement admission do
not change, and no files are deleted.

The maintainer requested this presentation correction. Moving optional
path-and-reason review from the modal to the existing Find Panel is an explicit
UX trade-off, not a new mandatory review step. The project judges 0.4.1 to be a
patch under its [versioning policy](../versioning.md) because eligibility,
completeness, and replacement guards are unchanged; this judgment does not make
all visible workflow changes patch-sized. The published 0.4.0 artifact is not
replaced, and the client is not bumped for this server-side change.
