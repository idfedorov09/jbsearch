# JB Search v0.2.2

JB Search is now presented as **JB Search — JetBrains-style Find & Replace**
and no longer carries the Marketplace Preview label. The extension ID remains
`idfedorov09.jbsearch`; existing installations receive the update normally.

## What's changed

- Short Marketplace installation instructions and a Usage section with
  Find/Replace shortcuts, Explorer folder search, and Remote SSH setup.
- A cleaner README without the duplicated large icon or preview copy, with
  badges for `master` CI and the published stable GitHub release.
- Updated platform evidence reflecting the user's successful macOS/Linux use.

The floating Find/Replace dialog, syntax-highlighted preview, native Find panel,
safe replacement behavior, and bundled client component are unchanged.

## Install

Install [JB Search from the Visual Studio Marketplace](https://marketplace.visualstudio.com/items?itemName=idfedorov09.jbsearch),
or search for **JB Search** in the VS Code Extensions view
(`Cmd+Shift+X` / `Ctrl+Shift+X`). Existing installations can update through Extensions.

Alternatively, download `jbsearch-0.2.2.vsix` from the assets below and use
**Extensions → … → Install from VSIX…**. `SHA256SUMS.txt` provides its checksum.

- `Cmd+Shift+F` / `Ctrl+Shift+F`: Find in Files.
- `Cmd+Shift+R` / `Ctrl+Shift+R`: Replace in Files.
- Right-click an Explorer folder and choose **JB Search: Find in Files…**
  to search within that directory.

With Remote SSH, the required local client component is installed automatically
when needed. No separate application or server-side theme installation is required.

## Requirements and validation

Desktop VS Code **1.143.1+** and a filesystem workspace are required. The
universal VSIX includes search executables for macOS, Windows, and Linux.
The user confirmed successful macOS and Linux use; Windows execution has not
been reported. Earlier automated GUI checks ran in actual Linux/X11 VS Code
windows. Physical Remote between separate machines, WSL, and Dev Containers
still need dedicated acceptance.

The modal uses an internal VS Code command and requires
`workbench.editor.useModal` to differ from `off`. Its read-only preview uses
TextMate without semantic tokens; results open in the full regular editor.
Search sessions are in memory and reset when the extension host restarts.
