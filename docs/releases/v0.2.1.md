# JB Search v0.2.1 — Preview

The first GitHub preview of JB Search brings a familiar JetBrains-style
Find/Replace workflow to desktop Visual Studio Code.

## Highlights

- Search and replace from a movable, resizable, theme-aware dialog with a
  syntax-highlighted code preview and highlighted matches.
- Search the project, a folder or directory, open editors, or named scopes;
  use file masks, multiline queries, regular expressions, Match Case, and
  Whole Words.
- Open the native Find panel to navigate a stable results tree with your VS Code
  file icons. Open a result in the regular editor to edit it; stale matches are
  marked **INVALID**, and guarded replacements support Undo.
- Start Find or Replace from the keyboard, or choose **JB Search: Find in
  Files…** from an Explorer folder's context menu.
- Use the bundled client component for theme and TextMate grammar resources in
  Remote; search queries and source contents stay on the workspace host.

## Install

Download `jbsearch-0.2.1.vsix` from the assets below. In desktop VS Code,
open the Extensions view, choose **… → Install from VSIX…**, select the file,
and reload the window when prompted. The main package includes the client UI
component used by Remote preview; it does not need a separate download.

The extension requires VS Code 1.143.1 or newer and a filesystem workspace.
VS Code for the Web and virtual workspaces are not supported.

## Preview status and known limitations

- Automated GUI checks have run in actual VS Code windows on Linux/X11. Manual
  acceptance on macOS, Windows, and Remote SSH between separate physical
  machines remains open; WSL and Dev Containers are unverified.
- The floating dialog uses an internal VS Code command, so compatibility with
  future VS Code versions is not guaranteed. `workbench.editor.useModal` must
  not be `off`.
- The dialog preview is read-only and uses TextMate rather than semantic tokens.
  A result opened in the regular editor retains normal language support.
- Search history is in memory and resets when the extension host restarts.
  Binary, UTF-16, oversized, and inaccessible files are skipped and reported;
  symbolic links are not followed.
