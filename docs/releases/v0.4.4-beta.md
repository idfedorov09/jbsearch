# JB Search 0.4.4 pre-release

This pre-release reduces the existing universal VSIX by omitting repository
demonstration images. It retains the icon, the bundled UI client, all 12
currently supplied ripgrep executables, and HTTPS README links to the images.
The extension ID remains `idfedorov09.jbsearch`; the bundled client remains
at 0.1.0. Search and replacement logic are unchanged from stable 0.4.3.

The repository also has a non-publishing build matrix for Windows, macOS, and
Linux x64/ARM64 plus a universal fallback. **The current Marketplace and Open
VSX publication workflows still publish only the universal VSIX.** Matrix
build artifacts are not gallery releases or proof of automatic target selection.
Gallery publication of the platform matrix needs a separate change and review.

At preparation on November 13, 2026, 0.4.3 was the highest published version
on both registries. Version 0.4.4 was chosen as a compatible patch, with the
pre-release marker separate from the numeric version. A later stable release
must use a distinct, higher version. Check the actual registry records rather
than treating this note as proof of publication.

## Verification and limitations

[The 0.4.4 candidate](../testing/platform-packaging.md) passed `npm run check`,
949 automated tests, strict OpenSpec validation, stable and pre-release
universal packaging, and a seven-artifact pre-release matrix build locally.
The universal candidates retained 86 main and 31 bundled-client entries.

[Platform packaging validation](../testing/platform-packaging.md) records the
stable and pre-release matrix builds, package contents and sizes, and an
installed Linux x64 VSIX test in VS Code 1.144.1. Those measurements and GUI
checks used the development manifest 0.4.2 before this version-only release
bump; they do not establish Windows, macOS, physical Remote, gallery selection,
or offline README-image availability. A local manual installation in that VS
Code version accepted a Windows VSIX on Linux, but searching then failed because
the Linux binary was absent. Choose the package for the workspace host or the
universal fallback.

The existing pre-release workflows build and verify their universal package on
the `beta` push and then publish to the registries subject to their protected
environments. Inspect the actual workflow results and registry records to
establish whether this pre-release was published.
