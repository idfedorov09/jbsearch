# JB Search 0.4.0 pre-release

This is the release note for a **pre-release candidate**, not a stable release
or evidence that public registry publication has completed. The extension keeps
the ID `idfedorov09.jbsearch`; the bundled UI client remains 0.1.0.

## Version decision

This batch contains fixes as well as the new
`jbsearch.replace.prepareTimeoutMs` setting, modal Rerun affordance,
match-context Replace All entry, and material action-admission/review changes.
The [project versioning policy](../versioning.md) therefore treats it as a
minor `0.x` release, not solely a patch. The unpublished `0.3.3` draft was
renumbered before publication; no published artifact was replaced.

Choosing `0.4.0` is a project judgment, not a SemVer requirement before `1.0`.
A first `1.x` release remains a separate deliberate compatibility commitment;
the size of this batch does not establish it, and a pre-release is not stable
or platform acceptance.

## Issue #3 changes

- Configure replacement preparation with `jbsearch.replace.prepareTimeoutMs`;
  the default is 60000 ms and the allowed range is 100–300000 ms.
- Completed Find Panel results stay as a stable snapshot through source events.
  New matches require **Rerun Search** rather than appearing silently.
- Supported edits track occurrence identity and validate source authority.
  Stale, ambiguous, pending, or unverified occurrences block affected actions.
- Replace actions use a bound reviewed snapshot. Replace All performs a fresh
  full-scope preflight and refuses if the current plan differs or is incomplete.
- Presentation updates preserve the supported model-level ordering and anchors;
  native TreeView selection, visual scroll, and delayed handle delivery remain
  separate acceptance boundaries.

These safeguards do not establish a global filesystem transaction or guarantee
zero edits after a submitted host edit fails. Review diagnostics and the actual
replacement preview before applying changes.

## Verification and boundaries

The integrated source's Linux automated checks and independent reviews are
recorded in [issue-3-dev-beta-validation.md](../testing/issue-3-dev-beta-validation.md).
The external v4 native-check attempt stopped before its runner started because
of a test-supervisor ownership-monitoring error. It established neither a native
application result nor a product failure. Further review of the repaired
external supervisor found receipt-validation defects, so another application
attempt remains blocked pending repair and independent review. Windows, WSL,
macOS, and a physical Remote connection have not been accepted for
this change. Headless Chromium, Node tests, and packaging are not substitutes for
real VS Code platform testing. Public release and exact registry verification
must be recorded separately when they actually occur.

An Open VSX consumer asking for unversioned `latest` can see a newer pre-release;
individual clients' update behavior has not been established by this record.
