# JB Search 0.4.7 stable release candidate

This document describes the stable candidate based on the verified 0.4.6 beta;
it is not by itself evidence that stable publication succeeded. Publication
status must be established separately for each registry and target.

## Changes since stable 0.4.3

- Exclude repository demonstration screenshots and the GIF from VSIX packages,
  retaining the icon and required runtime resources.
- Publish platform-specific VSIX files for Windows, macOS and Linux on x64 and
  ARM64, plus a universal fallback containing the full existing native binary
  inventory. The same extension identity is used for every package.
- Validate every package before publication and verify exact gallery identity,
  version, target, stable channel and SHA-256. A skipped or conflicting duplicate
  is not proof of a matching artifact; partial publication is reported explicitly.
- Preserve sequential uploads while overlapping bounded exact verification, and
  distinguish publisher completion from secret-safe verification diagnostics.

This is a compatible distribution and publication change. Find/Replace behavior,
settings, the extension ID, and the bundled client source and protocol are
unchanged. The main extension version is separate from the client version 0.1.0.

## Beta evidence and version

The `0.4.6` pre-release was merged through reviewed PR #10 and published to both
registries on November 14, 2026 (Moscow time). All seven exact records in each
registry were independently checked against GitHub's 0.4.6 beta build artifacts
for target, pre-release marker and SHA-256. The Marketplace publication loop
ran in about 13 minutes and Open VSX in about 4 minutes 10 seconds; these single
runs do not establish future registry latency. See the
[verification record](../testing/publication-overlap.md).

The stable candidate uses a distinct, higher numeric version **0.4.7**, in line
with the [versioning policy](../versioning.md). The stable artifacts differ from
beta because of their version and channel; build and verify them independently.
Marketplace stable publication follows the `master` push, while Open VSX stable
publication requires its separate manual `master` dispatch.

On November 14, the stable candidate passed `npm run check`, 1,004 automated
tests and strict validation of 40 OpenSpec items. A clean temporary installation
built and checked the default universal package and all seven stable packages.
That local matrix used a test epoch, not the final `master` commit timestamp;
its hashes do not establish the contents published to either registry.

## Boundaries

A successful build or gallery record does not prove that a client selects the
intended target or that every native platform and Remote scenario has been
accepted. Windows/macOS native execution, mixed-platform Remote and the existing
Windows/WSL issue #3 scenario remain unverified for this change. Publication is
not atomic; inspect every exact target and digest after a failure before retrying.
No tag or GitHub Release is created by the publication workflow itself.
