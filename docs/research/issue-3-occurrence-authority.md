## Implemented authority policy in this worktree

- Initial/full-search request policy is `disk-clean-buffers-dirty`. Clean local files, including clean Open Editors buffers, are searched from disk: a stale clean buffer with zero matches cannot hide actual disk matches. A known clean opened Unicode codec can be used explicitly; unsupported legacy codecs are blocking, not guessed. Unopened disk discovery retains strict UTF-8 handling.
- Dirty file buffers are searched from bounded current snapshots and carry a separate, stable raw-byte disk observation. The texts are **not** compared. Missing, oversized, unsafe or unavailable disk observations leave visible buffer matches blocked and the search incomplete. Untitled buffers have no disk overwrite baseline.
- `buffer-validation` searches only full current text and never overwrites original source provenance. Known versions/deltas can preserve dirty occurrences, while unknown history, destroyed/colliding anchors, ambiguous zero-width changes and failed/incomplete validation cannot.
- Save records a session-local ticket, not a disk read. Lazy preparation requires the same document object/URI, exact version/hash/encoding, clean state, generation, search fingerprint and current event epoch, plus current known row identities/revisions. It checks these again after asynchronous boundaries. Atomic Save may produce a new inode; equality of the current clean saved text is the selected contract. Another writer producing exactly that state is not distinguished by authorship.
- Unknown occurrence identity is never repaired by equality. A dirty edit after an observed Save but before any accepted rebase can still require a later clean Save or Rerun: the implementation does not silently compare the new dirty text with disk. Once a baseline is accepted, ordinary continuously tracked dirty edits can use it while its raw bytes remain unchanged.

## No-follow and platform policy

[Node 22.12.0's `fs` constants documentation](https://github.com/nodejs/node/blob/v22.12.0/doc/api/fs.md#L7752-L7851) does not expose `O_NOFOLLOW` or `O_SYMLINK` on Windows; the pinned [libuv Windows definitions](https://github.com/nodejs/node/blob/v22.12.0/deps/uv/include/uv/win.h#L686-L703) set their native mappings to zero. No undocumented Win32 bridge or new runtime codec dependency is introduced.

Two explicit baseline policies are kept separate and recorded as `linkPolicy`. Where supported, `no-follow` uses `O_NOFOLLOW` for the final component. An initial ordinary baseline may explicitly use `identity-validated`: lstat/open/fstat, bounded same-handle reads, post-read fstat/lstat, regular-file metadata/identity and the raw hash. On a capable host this still uses no-follow and records the stronger actual policy; otherwise it records identity validation, **not** a no-follow guarantee. Subsequent checks preserve the frozen baseline's recorded policy and cannot downgrade it.

Observed-Save rebase requires strict no-follow. On a host without that capability it refuses with Rerun guidance; unchanged initial baselines, trusted dirty edits and untitled buffers are not disabled wholesale. Neither policy protects every ancestor-directory symlink/junction race, proves author provenance, detects every adversarial ABA change or makes WorkspaceEdit atomic. Capability simulation is not native Windows verification.

## Resources and integration boundary

Document snapshots inspect EOF length without obtaining an arbitrarily large last line, then enforce the configured UTF-8 byte budget and a 128 MiB hard cap. Baseline reads stream through at most 64 KiB scratch space, stop at the observed bounded size plus one byte, verify file state again, and close the descriptor. Fatal UTF-8/UTF-8 BOM/UTF-16LE/UTF-16BE decoding hashes exact UTF-16 code units; malformed input, wrong BOM and unsupported encodings cannot be accepted as a lossy equal state.

A controller-owned physical FS lane caps active whole baseline operations at four and waiting operations at 512. Caller cancellation/deadline does not release capacity until the underlying read **and close** actually settle; queued expired jobs do not start. This reuses the agent 2 gate, separately from its document-open lane. It does not promise cancellation of a kernel syscall or a bound on unrelated worker search I/O.

The local adapter and synthetic tests do not complete the independent native immutable action protocol, unified event/open route, full-scope Replace All preflight, or joint integration. Those remaining tasks are explicitly unchecked in OpenSpec. No new VS Code/EDH, Windows, WSL or physical Remote run is claimed.
