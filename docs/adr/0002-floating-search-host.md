# ADR 0002: Штатный modal editor как контейнер поиска

- Статус: Accepted
- Дата: 2026-11-03
- Связь: [design-floating-search](../../openspec/changes/design-floating-search/design.md)
- Доказательства: [исследование и реальный запуск](../research/modal-editor-feasibility.md)

Дополнение: минимум VS Code изменён на 1.143.1, а порядок пересоздания view
пересмотрен после Remote SSH проверки; см. [ADR 0004](0004-source-registration-and-vscode-compatibility.md).

## Контекст и подтверждённые требования

Нужен компактный плавающий диалог поверх текущего окна VS Code по Cmd+Shift+F,
как Find in Files JetBrains: перемещение/resize, привычные компоненты VS Code,
наследование темы, results и preview внутри. Переход к тому же поиску во вкладке —
дополнительное действие. Поставка — обычное расширение для стандартного VS Code.
Платформы первой продуктовой итерации: macOS, Windows, Linux. Companion и detached
editor не являются согласованными заменами требуемого интерфейса.

Предыдущий вывод о необходимости модифицировать VS Code оказался слишком
категоричным: с 1.110 существуют штатные modal editors. Проверка отдельного VSIX
на официальном VS Code 1.144.1 Linux/X11 подтвердила custom editor внутри такого
диалога, drag/resize, Esc, live theme и перенос во вкладку. Пользовательский VS Code
не патчился; proposed API и отдельное приложение не использовались.

## Решение

Использовать read-only CustomEditorProvider для URI сессии поиска. Его webview
размещается в нативном modal editor. Команда открытия проходит через маленький
адаптер к внутренней `_workbench.openWith`, группе `MODAL_GROUP = -4` и modal
options; остальные операции опираются на публичный API. Это **не стабильный
публичный способ открыть modal**: `ViewColumn.Modal` пока отсутствует.

При `workbench.editor.useModal: some` обычные файлы остаются во вкладках. В
проверенной версии это default; включать `all` не требуется. При `off` маршрут
молча даёт вкладку, поэтому адаптер обязан остановить открытие с объяснением,
не менять настройку скрыто и не выдавать вкладку за требуемое окно.

Рамка и управление окном — компоненты самого VS Code. Внутренний UI — webview
с semantic HTML controls и `--vscode-*`, без сторонней библиотеки компонентов.
Внутренние widgets workbench не экспортируются через публичный API. Нативный
TextEditor нельзя вставить в webview; выбран read-only TextMate renderer с
декорациями совпадений, описанный в [ADR 0003](0003-search-engine-and-session.md).
Постоянные предпочтения — штатный Settings UI.

В первой реализации адаптер при повторном открытии закрывал прежний view и
разрешал новый custom editor для URI сессии. На 1.144.1 прямой возврат retained
webview из вкладки в modal оставлял iframe в координатах `(0, 0)` с размером
`300 × 150`; отключение retainContextWhenHidden проблему не устраняло.
Пересоздание представления через публичный `WebviewPanel.dispose()` сохраняло
host state и восстанавливало layout локально. При Remote SSH обнаружилась гонка
порядка закрытия и открытия: новое представление теперь создаётся до закрытия
старого, с новым URI и той же сессией. Подробности и проверка — в ADR 0004.

## Варианты

| Вариант | Результат | Ограничение |
| --- | --- | --- |
| Modal editor + CustomEditorProvider + внутренний адаптер | Реально проверенный диалог поверх редактора; один VSIX; тема и штатное управление окном | Внутренняя команда и experimental механизм, нужна совместимость по версиям |
| Только документированный stable API | Webview, QuickPick, editor tabs | Нет публичного произвольного modal target; QuickPick недостаточен для требуемого preview |
| Webview + detached editor window | Один VSIX и отдельное окно редактора | Не компактный диалог поверх workbench |
| Electron/Tauri companion | Отдельное системное окно | Отдельная поставка и сложная связь фокуса, темы и окон; не требуется найденному пути |
| Inspector/DOM injection, как IntelliJ Styled Search | Очень близкий UX у существующего расширения | Глубокая зависимость от Electron/Monaco internals; не принята и не запускалась |

## Последствия и условия принятия

- Пользователь подтвердил реализацию 2026-11-03 после демонстрации. Внутренний
  API принят как ограниченная зависимость, не гарантия совместимости; готовность
  поиска определяется проверками.
- Совместимость проверена на 1.144.1 Linux/X11; этот номер выбран минимумом в
  manifest и адаптере. Windows/macOS и следующие версии требуют отдельных проверок;
  по номеру появления функции совместимость не выводить.
- Все недокументированные аргументы сосредоточить в одном адаптере; проверять
  supported versions/настройку, ошибки, повторное открытие и move-to-tab.
  Подготовить переход на публичный modal API при его появлении.
- Не включать `all`, не менять настройку `off` молча и не устанавливать companion
  в качестве незаметной замены при отсутствии modal.
- SearchSession живёт в extension host: Esc уничтожает view, но не должен терять
  запрос. Перенос в editor использует штатную команду; это не экспорт строки в
  встроенный Search Editor.
- UI находится в пределах workbench, без отдельного окна в Alt+Tab. Модальность,
  несколько окон, fullscreen, IME, HC/zoom и клавиши проверить отдельно.
- Remote/web не объявляются поддержанными только на основании desktop опыта.
