## Native Find provider and command boundary

Provider/controller regressions now verify the implemented immutable action
boundary rather than treating a mutable provider revision as client approval:

- Stable logical occurrence IDs are separate from non-reused native match
  handles. Each row captures a detached immutable generation/revision/action
  descriptor; a full token change replaces every match action/handle.
- Delayed old commands and context arguments are refused before and after
  asynchronous boundaries, including after reset, removal/reappearance and
  saved-session ABA. Explicit expired/undefined context arguments never fall
  back to the latest selection or toolbar review. Actual stale native selection
  also cannot activate an editor through the no-argument Open command.
- An explicit current row forwards its exact captured full binding for Single
  and All; no-argument toolbar Single/All omit it. Descriptor copying cannot
  create, upgrade or borrow the latest backend token.
- Status-only changes retain provider/native identity when action semantics are
  unchanged; changed row actions refresh their existing file parent, not a new
  child object unknown to VS Code. Ancestor counts, logical selection and
  deterministic `z,a` streaming to `a,z` completion remain covered.
- File group IDs are parent-qualified. Missing/duplicate logical result IDs and
  malformed/mismatched descriptors fail closed with a diagnostic, while busy
  guards permitting, Rerun/Edit/Close allow recovery. Session switching cannot
  erase malformed-descriptor rejection.

The delayed-handle test models the pinned extension-host handle-to-current-
element conversion before/after refresh. It is not a native frontend test, a
paint acknowledgement, or proof that the backend dispatched only approved edits.
No stale-handle history is retained by this provider.

### Independent backend compatibility guard

This checkout does not contain the replacement owner's immutable-manifest and
frozen-review backend. A small temporary `findMessage` compatibility guard
therefore refuses native replacement rather than letting a new native payload
fall through to the legacy unbound path. Its regression checks zero calls to
`applyEdit` for missing and supplied descriptors while that backend is absent.
The presence of a method named `reviewReplacement` is **not** a safety proof;
integration must deliberately reconcile/remove this guard and verify the actual
binding, manifest, identity and preflight admission on every dispatch path.
Ordinary reliably bound native actions must not remain blanket-disabled in the
combined implementation.

## Reproducible 50,000-row provider measurements

Run `node --expose-gc test/performance/find-tree.js`. This synthetic Linux/Node
**22.23.2** fixture has 50,000 rows in 1,000 files, each referencing the same
2,000-code-unit preview string, not 50,000 independent preview copies. Source and
variant fixtures are created before the baseline heap reading and excluded from
the retained increment. Each sample creates a fresh provider, rotates the path
order, uses two warm-up plus seven measured rounds and checks counts, logical
selection, notification kind and provider-object reuse. The timed interval is
only `FindTree.update`; forced GC is outside it.

| Path | Median ms (min–max) | Initial tree MiB | Updated tree MiB | Event / reused match objects |
| --- | ---: | ---: | ---: | --- |
| Unchanged rows / session notice | 138.82 (131.10–145.37) | 50.98 | 50.97 | none / 50,000 |
| One pending status, same action semantics | 152.16 (129.31–166.85) | 50.93 | 50.97 | 4 targeted nodes / 50,000 |
| One row action revision (isolated) | 149.85 (137.69–166.77) | 50.98 | 50.97 | 1 file parent / 49,999 |
| Whole-manifest descriptor revision | 255.06 (239.39–274.35) | 50.93 | 53.65 | 1,000 file parents / 0 |
| Structural reverse of all rows | 486.49 (432.71–513.30) | 50.98 | 51.02 | root / 0 |

`rowActionRevision` deliberately isolates one row change while retaining a
synthetic unchanged full binding. In the real combined contract a new complete
manifest token uses the separately measured `manifestRevision` path, even if
only one file changed. It is not valid to advertise the single-row figure as
the real whole-manifest cost.

Retained figures are approximate post-GC V8 `heapUsed` increments for this
provider, not peak RSS, native rendering, worker memory or workbench latency.
Multiple saved sessions retain separate trees. Full handle renewal also asks
VS Code to revisit each affected file parent; those client costs are not in the
timings. The earlier safety-incomplete fast-path experiment's approximately
`+9.93 MiB/tree` is historical and not a measurement of this immutable-action
implementation; fixtures/methods are not a controlled cross-version comparison.
None of these data establishes Windows, WSL or Remote performance.
